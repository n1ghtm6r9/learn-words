# Приложение для изучения слов — дизайн

Дата: 2026-08-17

## Цель

SPA на React для пополнения личного словаря (слово + перевод) и его заучивания через интервальные повторения (spaced repetition). Работает полностью офлайн, без бэкенда, все данные — локально в браузере.

## Стек

- **Build/lang:** Vite + React 19 + TypeScript
- **Стили/UI:** Tailwind CSS v4 + shadcn/ui (Base UI примитивы)
- **UI-состояние:** Zustand — только эфемерное состояние (текущий экран, активная сессия обучения, тема). Данные словаря НЕ хранятся в Zustand — они читаются напрямую из Dexie через `dexie-react-hooks` (`useLiveQuery`), чтобы UI сам обновлялся при изменениях в БД.
- **Хранилище:** Dexie.js (обёртка над IndexedDB) + `dexie-react-hooks`
- **Анимации:** Motion (бывший Framer Motion)
- **Озвучивание:** встроенный Web Speech API (`SpeechSynthesis`) — без внешних сервисов
- **Приятная мелочь:** `canvas-confetti` — короткая анимация по завершении сессии обучения
- **Роутинг:** отсутствует. Приложение маленькое (5 экранов), URL-навигация не даёт пользе — экраны переключаются через простой стейт в `useUIStore`.
- **Тесты:** Vitest + React Testing Library

## Модель данных (Dexie)

```ts
interface Word {
  id: number;
  term: string;          // слово на изучаемом языке
  translation: string;   // перевод
  category?: string;     // опциональная метка/тема
  createdAt: number;

  // SM-2 состояние
  easinessFactor: number; // стартовое 2.5
  interval: number;       // дней до следующего повторения, стартовое 0
  repetitions: number;    // сколько раз подряд отвечено верно, стартовое 0
  dueDate: number;        // timestamp, когда слово нужно повторить снова
  lastReviewedAt?: number;
}

interface ReviewLog {
  id: number;
  wordId: number;
  reviewedAt: number;
  correct: boolean;      // для статистики/streak
}
```

Новое слово создаётся с `dueDate = now` (сразу доступно к изучению), `easinessFactor = 2.5`, `interval = 0`, `repetitions = 0`.

## Алгоритм повторений (SM-2)

1. Пользователю показывается `term`, он вводит перевод.
2. Введённый текст сравнивается с `translation` через нечёткое сравнение (расстояние Левенштейна с допуском на длину строки):
   - точное совпадение → **verdict = correct**, SM-2 quality = 5
   - совпадение с 1–2 опечатками (для коротких слов допуск меньше) → **verdict = almost**, quality = 4, правильный ответ показывается пользователю
   - иначе → **verdict = wrong**, quality = 2, правильный ответ показывается
3. Пересчёт по стандартной формуле SM-2:
   - если `quality < 3`: `repetitions = 0`, `interval = 1`
   - иначе: `repetitions == 0` → `interval = 1`; `repetitions == 1` → `interval = 6`; иначе `interval = round(interval * EF)`; `repetitions += 1`
   - `EF = EF + (0.1 - (5-quality) * (0.08 + (5-quality) * 0.02))`, `EF` не ниже `1.3`
   - `dueDate = now + interval * 1 день`
4. Пишется запись в `reviews` (`correct = verdict !== 'wrong'`).

Очередь на сессию обучения: слова, где `dueDate <= now`, отсортированные по `dueDate` (просроченные — первые), с ограничением на размер сессии (например, 20 слов), чтобы не перегружать пользователя за раз.

## Экраны

Навигация — нижняя панель (мобильный layout) с 5 пунктами, состояние текущего экрана хранится в `useUIStore`.

1. **Главная** — сколько слов ждут повторения сегодня, всего слов в словаре, текущий streak (дней подряд с хотя бы одной сессией), кнопки быстрого доступа («Учить», «Добавить слово»).
2. **Добавить слово** — форма: слово, перевод, опциональная категория. Валидация: оба поля обязательны, дубликаты по `term` — предупреждение, но не блокировка.
3. **Учить** — карточка: слово (+ кнопка озвучки через Web Speech API), поле ввода перевода, кнопка проверки. После ответа — цветной фидбек (верно/почти/неверно) + правильный перевод, кнопка «Далее». Прогресс-бар «N из M» по сессии. По завершении сессии — экран итогов (сколько верно/неверно) + confetti.
4. **Мои слова** — список всех слов с поиском по тексту и фильтром по категории, редактирование и удаление слова.
5. **Статистика** — количество выученных слов (эвристика: `interval >= 21` дня = «выучено»), точность ответов за последние 7/30 дней (из `reviews`), календарь streak.

## Тестирование

- Юнит-тесты (Vitest) на `srs.ts` (расчёт EF/interval/repetitions по разным сценариям качества ответа) и `fuzzyMatch.ts` (граничные случаи опечаток) — это критичная логика, ошибка в ней тихо ломает весь смысл приложения.
- Smoke-тесты (RTL) на форму добавления слова и на прохождение одной сессии обучения (ответ → фидбек → следующий вопрос).
- E2E не нужен для v1 — приложение полностью локальное, без сети/бэкенда, юнит + smoke достаточно покрывают риск.
